POC — Private AI for small businesses

PMI AI Hub

Private AI for Italian small businesses.

Employees can read scanned quotes, ask questions about contracts and compare suppliers’ terms. They can edit Excel workbooks, create PowerPoint decks from a workbook or from a detailed brief, check current information on the web or request Deep Research with source links and a downloadable report. Knowledge bases and saved prompts can be shared with colleagues. Italian by default, from the interface to the chat titles.

Built on Open WebUI. The value is not the software — it's the two dozen defaults changed, each one measured, justified and written down.

01

One instance per company

No shared multi-tenant platform: every customer gets its own small VM on a European cloud, its own model-provider account and its own keys. A spent budget or a revoked key stops one customer, never the others.

02

What the user sees

The model picker offers these four profiles to employees.

PMI AI

GLM-5.2 · default

The main profile handles document questions and everyday work. Standard web search and Deep Research are available in the chat.

PMI AI Small

qwen3.8-27b

Handles everyday tasks and summarises long chats. In two chat API tests on Regolo on 16 November 2026, it correctly identified the colour, shape and order of objects in synthetic PNG images.

PMI AI Excel

Dedicated workbook profile · Pyodide

Opens with the code interpreter on and web search off. Reads, computes, modifies and returns the file.

PMI AI PowerPoint

Dedicated deck profile · Pyodide + python-pptx

Creates presentations, not just reads them. From scratch, starting from a long, detailed brief, or from a workbook ("three slides for the CEO"): it reads every row, computes the figures in code, checks them against the sheet's own totals and returns a ready .pptx. Attach an existing deck and it becomes the template.

Background tasks. A separate model (Gemma 4 31B) generates titles, tags and follow-up suggestions.

Personal or shared

Every user can build knowledge bases and share them with colleagues or groups. Public sharing stays off.

Kept until removed

Knowledge base documents don't expire with the 90-day purge — chat attachments do. Both are stated in the privacy notice.

A scanned quote, checked end to end

In a test with an image-only PDF, the chat upload correctly recovered the item “Pompa”, quantity 24 and price 175 EUR. This checks the upload path on one synthetic quote. Accuracy on customers’ scans still needs testing.

What the model reads. Focused retrieval is the default. For “What does the pump cost?”, Open WebUI sends relevant passages to the chat model. For “Compare all the exclusions in these two quotes”, select the entire document on each attachment. The model then receives both extracted texts, subject to its context limit. Asking for “all” does not change the attachment setting.

05

Features

What a small company actually asks for: a chat that is safer than the free tools employees already use, that works on their files, and that someone else keeps running.

Office files in chat

Excel: livePowerPoint: practically readyWord: plannedruns in the browser

With the code interpreter enabled, the assistant can run Python in the employee’s browser (Pyodide) to calculate from workbook cells. A dedicated model knows the traps — totals rows, Excel Tables to extend, files with macros or charts to warn about. PowerPoint goes one step further: the assistant creates decks. Write a detailed brief and get a complete deck built from scratch, or hand it a workbook and download a .pptx built from computed figures, each one traced to its source. Verified in tests and already refined in a first Evaluation Loop, it is practically ready. Word will follow the same flow: upload, ask, get the file back.

Privacy by design

no chat logs90-day retentionaudit without content

No log of conversations. The admin can't browse employees' chats from the interface. Accesses and admin changes are audited — who, when, from where — never what was asked.

Web search and Deep Research

Deep Research: betacited sources

The assistant can check current facts on the web or carry out a deeper investigation when requested. Deep Research checks quantitative claims against retrieved source passages and produces a cited summary with a complete Markdown report to read or download. A second model reviews the draft before it is published. Both research options can stay enabled, with one mode used per request.

Shared knowledge and prompts

Users build their own knowledge bases and saved prompts and share them with colleagues or groups. Public sharing stays off.

Italian first

Interface in Italian by default, chat titles always in Italian, and a chat that opens with "ciao" is titled "Nuova conversazione" instead of an English "Empty Conversation". Follow-up suggestions follow the language of the chat.

Status page — traffic lights

One password-protected page, checked live on every open: app, model provider, disk, RAM, last night's backup, failed logins, today's users and chats. No alerting stack on a 5-person company's VM.

Controls, not instructions. Which tools a model can call is filtered server-side, before the tool list reaches the model — for it, the removed tools don't exist. A system prompt that asks for caution is a sentence the model may ignore; a filter is a limit. The same mechanism can give everyone read access to an internal system and only some people write access.

07

Key architectural decisions

No gateway in front of the models

ProblemGateway stacks add governance a 10-person company never uses — and more parts to patch.
ChoiceGovernance inside the interface; one instance and one provider key per customer.
ResultOpen WebUI, Caddy and Docling run on the company VM. Each customer controls its own model-provider budget.

No conversation logs

Problem"Log everything" means a register of employees to justify and sensitive data to guard.
ChoiceAudit of accesses without content; admin chat reading and export off.
ResultOne sentence for the privacy notice: chats are deleted 90 days after last use and gone from backups within 14 more.

Excel computed in the browser

ProblemModels guess numbers; server-side sandboxes run model-written code on the customer's VM.
ChoicePyodide interpreter in the user's browser + a dedicated model with Excel rules.
ResultFile read, modified, returned — and reopened in Excel without repair.

A context budget the product never had

ProblemThe interface counts tool iterations, not tokens or euros — 256 by default.
Choice40 iterations, output caps of 16k (32k for Excel), compaction thresholds per model.
ResultIn the 15 October 2026 test on Regolo, compaction reduced a chat from 41.5k to 13.9k tokens while preserving the facts needed for the answer.

Upgrades as part of the service

ProblemA moving tag pulls a different image on a new machine; database migrations don't roll back.
ChoiceDigest pinning, "new version" notice off, upgrades tested on the template first.
Result0.12.2 → 0.13.3 on 16 November and 0.13.4 on 22 November 2026, each with backups and post-upgrade checks.

Measure the model before exposing it

ProblemDeclared context windows and real ones don't match.
ChoiceThree sources per model: engine error, provider metadata, real long prompt.
ResultOne model excluded for a 30k declared input window; thresholds set on data, not on labels.

Vector search only, no reranker

ProblemRegolo's reranker ranked Italian passages badly; running another model locally would add load to the VM.
ChoiceFocused retrieval uses vector search with top-k set to 20. Employees can also select the full extracted text.
ResultNo GPU, one provider. To be re-measured on the first customer's real documents.
08

Problems solved

Long prompts failed on the default model

SymptomHTTP 400 with only 6–12k tokens of input.
CauseIn October 2026, Regolo injected a 200k output budget on GLM-5.2 when the client omitted the limit.
FixAn explicit 16k output cap let the same 30k-token input complete in 9.1s in the 15 October 2026 Regolo test.

New models invisible to users

SymptomA model added by the admin never showed up for employees. No error.
CausePer-model grants — and the admin always sees everything.
FixVisibility decided by the connection's whitelist; every check now done as an end user.

Deleted wasn't deleted

SymptomA file removed from the app still had its text in the vector database.
CauseDeleting a file doesn't delete its embeddings.
FixThe purge removes vectors first; the technical residue is declared in the notice.

Admin "chat access off" — but not quite

SymptomWith chat access disabled, the analytics API still returned message text and reasoning.
CauseThe flag covers the interface, not the statistics endpoint.
FixKept, verified and declared — a layered wall, written up for the privacy consultant.

A sidebar full of "Empty Conversation"

SymptomChats opened with "ciao" got an English, useless title — forever.
CauseThe title is generated once, from the first exchange, in English when unsure.
FixItalian title template with a "Nuova conversazione" rule. The October 2026 test on Regolo took 0.4s per title.

Modified Excel opened only after "repair"

SymptomExcel asked to repair the file the model returned.
CauseValues written into the totals row; the Excel Table not extended.
FixExplicit rules in the Excel model — file reopened clean.

Requests that never ended

SymptomAbout one chat request in three hung: no answer, no error, a spinner forever.
CauseThe provider kept the stream open without sending data, and Open WebUI waits with no limit by default.
FixA stream silent for 60 seconds is closed with a clear error in chat. The product moved back to Regolo.

Confident answers on old versions

SymptomAsked for the latest Open WebUI release, the assistant named an old one.
CauseThe model did not know today's date and answered from search snippets.
FixThe prompt carries today's date and asks to open the main source for versions, prices, dates and news.

Lesson: verify the content, not the status code — a 200 can carry an empty answer, or the web app's own HTML.

09

What's next

One-command deploy

Half of the configuration lives in the database, not in files. Today a new instance is a move of the template; the goal is a script that builds a clean customer instance from zero — keys, name, notice — and verifies it as an end user.

Hardening before the first customer

A real Let's Encrypt certificate on an EU VM, two-factor authentication for local accounts, off-site backups, and an alert when the service or the provider goes down.

Enhanced edition

Same workspace with a LiteLLM gateway in front of the models and full Microsoft 365 integration, for companies that outgrow the light version.

PowerPoint release, then Word

PowerPoint creation already works in tests: next comes the release, after a wider Evaluation Loop on real company files. Word follows the same seamless flow: documents with the company letterhead, or upload one and get it back edited. Candidate tools for Word reviewed; code to be audited and pinned before any install.

A European web search

Offer a European search engine when a customer requires it.
